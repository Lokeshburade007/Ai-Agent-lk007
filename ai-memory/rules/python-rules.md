# Python / FastAPI Rules

Load this when working on any Python backend project. Tuned for **FastAPI + SQLAlchemy 2.0 + Alembic + Pydantic v2 + Postgres**.

## Always

- **Type hints on every function signature.** FastAPI and Pydantic both rely on them; missing hints silently break dependency injection and request validation.
- **Async-first.** Route handlers are `async def` unless they call only sync libraries. `def` is fine; FastAPI runs sync handlers in a threadpool. Never mix `await` inside `def`.
- **Pydantic v2 `BaseModel`** for request/response shapes — never raw dicts. Use `Field(..., description=...)` for OpenAPI docs.
- **Separate models for input / output / DB.** Don't return a SQLAlchemy ORM object directly. Convert via a Pydantic response model with `from_attributes=True`.
- **Dependency injection via `Depends(...)`** for DB sessions, current user, settings. One source of truth per dependency.
- **`pydantic-settings`** for config. One `Settings` class, loaded at startup, injected via `lru_cache`. No scattered `os.environ.get` calls.
- **SQLAlchemy 2.0 style:** `select(User).where(...)`. Never the deprecated `session.query(User)` API.
- **Alembic** for migrations. Generate, **review the autogenerated diff manually**, never trust autogenerate blindly (it misses index renames, constraint changes).
- **`uvicorn` + `--reload`** for dev, **gunicorn + uvicorn workers** for prod.
- **`structlog` or stdlib `logging` with JSON formatter** for production logs. Never `print` in handlers.
- **HTTP status codes** match semantics (201 create, 204 empty, 400 client, 401 auth, 403 forbidden, 404 not found, 409 conflict, 422 validation, 429 rate limit). FastAPI returns 422 automatically on validation failure — don't fight it.

## Never

- ❌ Catch `Exception` broadly without re-raising. If you mean a specific case, catch the specific type.
- ❌ Pass raw user input into SQL strings (`text("SELECT ... " + user_input)`). Always parameterize.
- ❌ Use `eval`, `exec`, or `pickle.loads` on untrusted data.
- ❌ Mutate `datetime.utcnow()` or assume UTC. Use `datetime.now(timezone.utc)` (PEP 495).
- ❌ Use `requests` in `async def` handlers — it blocks the event loop. Use `httpx.AsyncClient` instead.
- ❌ Open DB sessions in module scope. Get them via `Depends(get_db)` so they're scoped to the request.
- ❌ Run blocking I/O directly in an `async` route (CPU-heavy work, file I/O). Wrap with `asyncio.to_thread` or move to a worker.
- ❌ Put business logic in router functions. Routers translate HTTP ↔ services; services own the logic.
- ❌ Skip `__init__.py` for packages — implicit namespace packages cause subtle import issues.

## File layout

```
app/
  main.py                  # FastAPI app + middleware + routers wired
  config.py                # Settings (pydantic-settings)
  database.py              # engine, SessionLocal, get_db dependency
  models/                  # SQLAlchemy ORM models
    __init__.py
    user.py
  schemas/                 # Pydantic models (request + response)
    __init__.py
    user.py
  routers/                 # APIRouter modules — one per resource
    __init__.py
    users.py
  services/                # business logic, framework-agnostic
    __init__.py
    user_service.py
  repositories/            # DB access, returns ORM objects
    __init__.py
    user_repo.py
  dependencies/            # reusable Depends(...) (auth, pagination)
    __init__.py
    auth.py
  middlewares/             # custom middleware
  utils/                   # small pure helpers
  exceptions.py            # AppException base + subclasses
alembic/                   # migrations
tests/
  conftest.py              # fixtures, test DB override
  test_*.py
```

## SQLAlchemy 2.0 patterns

```python
# repositories/user_repo.py
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

async def get_by_id(db: AsyncSession, user_id: UUID) -> User | None:
    return await db.scalar(select(User).where(User.id == user_id))

async def list_active(db: AsyncSession, limit: int = 20, cursor: str | None = None) -> list[User]:
    stmt = select(User).where(User.deleted_at.is_(None)).order_by(User.created_at).limit(limit)
    if cursor:
        stmt = stmt.where(User.created_at > decode_cursor(cursor))
    return list(await db.scalars(stmt))
```

## FastAPI handler shape

```python
# routers/users.py
from fastapi import APIRouter, Depends, HTTPException, status
from app.dependencies.auth import get_current_user
from app.schemas.user import UserOut, UserCreate

router = APIRouter(prefix="/users", tags=["users"])

@router.get("/me", response_model=UserOut, status_code=status.HTTP_200_OK)
async def get_me(current_user: User = Depends(get_current_user)) -> UserOut:
    return UserOut.model_validate(current_user)

@router.post("", response_model=UserOut, status_code=status.HTTP_201_CREATED)
async def create_user(
    payload: UserCreate,
    db: AsyncSession = Depends(get_db),
    service: UserService = Depends(get_user_service),
) -> UserOut:
    user = await service.create(db, payload)
    return UserOut.model_validate(user)
```

Routers stay thin. Services own the rules. Repositories own the queries.

## Error handling pattern

```python
# exceptions.py
class AppException(Exception):
    status_code: int = 500
    code: str = "internal_error"
    def __init__(self, message: str, **extra): ...

class NotFoundError(AppException):
    status_code = 404
    code = "not_found"

# main.py
@app.exception_handler(AppException)
async def app_exc_handler(request, exc: AppException):
    return JSONResponse(
        status_code=exc.status_code,
        content={"error": {"code": exc.code, "message": str(exc)}},
    )
```

Raise `NotFoundError("user not found")` from services. The handler translates to HTTP. Never `raise HTTPException(...)` inside services — that couples them to FastAPI.

## Pydantic v2 specifics

- `BaseModel` with `model_config = ConfigDict(from_attributes=True)` to load from SQLAlchemy ORM.
- `Field(..., min_length=8, description="...")` for validation + docs.
- `@field_validator("email")` for cross-field rules.
- `model_dump()` not the deprecated `dict()`.
- `model_validate()` not `parse_obj()`.

## Alembic migration discipline

- Run `alembic revision --autogenerate -m "<message>"`.
- **Open the generated file. Read it line by line.** Autogenerate misses:
  - Renames (it sees drop + add — destructive)
  - Index name changes
  - Constraint changes
  - Type changes that need data migration
- Add an `op.execute(...)` block for data backfills if needed.
- Never edit a committed migration. Make a follow-up.
- For zero-downtime: add nullable column → backfill → set NOT NULL in next migration.

## Config (pydantic-settings)

```python
# config.py
from functools import lru_cache
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    database_url: str
    jwt_secret: str
    jwt_access_ttl_seconds: int = 900
    log_level: str = "INFO"
    model_config = SettingsConfigDict(env_file=".env", case_sensitive=False)

@lru_cache
def get_settings() -> Settings:
    return Settings()  # crashes on missing required env — intentional
```

Inject into routes:
```python
@router.get("/version")
async def version(settings: Settings = Depends(get_settings)): ...
```

## Testing

- **pytest + pytest-asyncio + httpx.AsyncClient** for async tests.
- `TestClient` (sync) for simple cases, `AsyncClient` (real async) when testing concurrency.
- Override dependencies in tests with `app.dependency_overrides[get_db] = lambda: test_db`.
- Use **Testcontainers** or **pytest-postgresql** for a real Postgres in integration tests.
- Use **transaction rollback per test** (start a transaction in fixture, rollback in teardown) — faster than truncate.
- Don't mock SQLAlchemy. Mock the repository interface or use a real DB.

## Background work

- **`BackgroundTasks`** for fire-and-forget *within the request* (send email after returning). Not durable; lost on crash.
- **Celery / RQ / arq** when you need durability, retries, scheduling.
- Don't use `asyncio.create_task` from a handler unless you're sure the task lifetime fits the request.

## Security defaults

- Passwords: `passlib[bcrypt]` with cost 12+, or `argon2-cffi`.
- JWT: `python-jose` or `PyJWT`. Short-lived access (15min) + refresh tokens rotated on use.
- `python-multipart` for form parsing (FastAPI requires it for OAuth2 password flow).
- CORS: explicit allowlist in `CORSMiddleware`. Never `["*"]` with credentials.
- Rate limit with `slowapi` (Redis backend in prod).
- Trust proxy headers only with `--proxy-headers` and known reverse proxy.
